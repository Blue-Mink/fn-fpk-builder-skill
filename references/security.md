# FPK 安全基线

本页把构建输入、归档、生命周期脚本、网络入口、供应链和远程设备视为同一条信任链。发现高风险问题时应阻止构建或部署，而不是只打印提示。

依据：`https://developer.fnnas.com/llms-full.txt` 中的 `docs/core-concepts/` 内容，以及 fnpack 1.2.3 产物的独立安全审计。

## 风险分级

阻断错误：

- 路径穿越、绝对路径或指向归档外的链接。
- FPK 与目标设备架构不一致。
- Mach-O、PE 或混合 ELF 架构进入 Linux FPK。
- manifest、checksum 或必需 JSON 无法验证。
- 私钥、Token、真实 env 文件等明显秘密进入包。
- 工具下载哈希不一致。
- 未确认目标的卸载或清理。

警告但不自动改写：

- `run-as=root`。
- CGI、统一网关、公开端口或管理员入口。
- 浮动 Docker tag。
- 宽泛共享目录或附加系统组。
- 缺少可复现锁文件、SBOM 或来源记录。

工具不应擅自把 root 改成 package、改端口或删除业务资源；它应解释风险并要求开发者确认设计。

## 归档安全

在解压外层 FPK 和内层 `app.tgz` 前：

- 使用 POSIX 方式规范化 `/` 分隔符。
- 拒绝绝对路径、父级 `..` 分量、NUL、控制字符和反斜杠路径；允许 tar 工具生成的无害根目录 `.` 条目，但绝不提取它覆盖目标。
- 检测不同文本路径规范化到同一目标的重复条目。
- 拒绝字符/块设备、FIFO 等特殊节点。
- 验证 symlink/hardlink 的最终目标仍在提取根目录内。
- 先完整检查成员，再执行提取。
- 限制成员数量、单文件大小和总解压大小，防止资源耗尽。
- 不跟随目标目录中预先存在的链接。
- 扫描内层 `app/` 与外层 `cmd/` 等所有普通文件；生命周期入口也可能是 ELF，不能只检查应用载荷目录。

不要使用普通 `tar.extractall()` 处理未经验证的 FPK。检查与提取之间应使用新建、权限受控且本任务独占的临时目录。

`manifest.checksum` 按当前 fnpack 1.2.3 实测为 `app.tgz` 的 MD5。MD5 只用于格式一致性，不提供发布供应链安全；外层 `.fpk` 必须另算 SHA-256。

## 秘密与无关文件

必须检测或排除：

- `.env`、`.env.*`、安装向导真实 env。
- SSH 私钥、PEM、P12/PFX、云凭据和 npm/pip registry token。
- `.git/`、CI runner 配置、编辑器历史。
- `.DS_Store`、`Thumbs.db`、交换文件。
- 测试数据库、生产日志、core dump。
- 未必要的源码缓存、构建缓存和另一个平台的产物。

仅靠文件名不能发现全部秘密；对文本文件补充高置信模式扫描。扫描结果展示路径和类型，不回显秘密正文。

fnpack 1.2.3 实测会把 staging 中的 `.DS_Store` 原样带入 FPK，因此 staging 审计是必需步骤。

## 权限和生命周期

- 默认 `run-as=package`。
- `join-groups` 只加入真正需要的组。
- root 初始化完成后，以专用用户启动长期进程。
- 配置、PID、socket 和日志放在系统提供的应用目录。
- shell 中所有路径和用户输入加引号。
- 不使用 `eval`，不把向导值或请求参数拼接成命令。
- 临时文件使用不可预测的唯一目录，并设置合适权限。
- PID 检查同时验证进程身份，避免杀死复用 PID 的其他进程。
- stop 先 TERM、限时等待，再按需 KILL。
- 卸载尊重用户选择，不默认删除持久数据或共享目录。
- 失败信息写入 `TRIM_TEMP_LOGFILE`，但不得包含密码、Token 或完整环境。

资源声明应遵循最小权限。`usr-local-linker` 的命令名使用应用前缀，避免覆盖通用系统命令。

## 入口与业务鉴权

端口入口：

- 不自动获得 NAS 会话身份。
- 明确监听地址；不需要 LAN 暴露时只监听本地接口。
- 自行实现认证、CSRF、防暴力尝试和 TLS 边界。

CGI：

- 标准化 URL 路径后再映射文件。
- 拒绝 `..`、编码绕过和符号链接逃逸。
- 不把请求参数交给 shell。
- 返回正确状态码和安全 Content-Type。

统一网关：

- 只信任经网关到达的 `X-Trim-*` 身份 Header。
- 若服务还能被端口或其他 socket 直连，不能无条件信任同名客户端 Header。
- 登录态不等于业务授权；管理员接口检查 `X-Trim-Isadmin`，用户数据绑定 `X-Trim-Userid`。
- WebSocket 在握手时绑定身份，不接受消息正文自报用户 ID。
- 文件 ID、路径和记录 ID 均结合当前用户授权验证。

OAuth 回调或其他公开路径只开放必要方法、字段和速率，不能为了回调把整个 API 设为未鉴权。

## 供应链

- fnpack 和其他下载工具固定版本与 SHA-256。
- GitHub Actions 固定完整 commit SHA。
- 语言依赖使用 lockfile 和 frozen 模式。
- Docker 镜像固定 digest，并核对多架构 manifest。
- 记录源 commit、工具版本、目标架构和产物 SHA。
- 不执行包内或 overlay 内未审查的任意构建命令。
- 不从 pull request artifact 直接进入带生产凭据的发布 job。
- 构建与签发/发布分离，后者只消费已经验证的不可变制品。

发布时优先生成来源证明和 SBOM；即使当前分发渠道不强制，也保留可追踪证据。

## 远程操作

- 默认只读。
- host 必须由用户提供，保留 SSH 主机密钥验证。
- 上传后在远端复算 SHA-256。
- 安装后逐个核对 `app.tgz` 中所有普通文件的 SHA-256 与实际 `/var/apps/{app}/target` 内容，并拒绝文件数量差异。
- 使用唯一临时路径，不清空共享 `/tmp` 目录。
- 原位升级是默认；完全卸载须 `--clean`，独立卸载须 `--yes`。
- 环境文件上传后权限 600，操作完成立即删除。
- 失败时保留应用中心错误和状态证据，但清理本任务秘密。
- 日志输出执行高置信秘密遮蔽；不能因此把原始日志视为可公开内容。
- 回滚包必须由用户明确指定并先审计，恢复后再次核对状态、版本和 manifest。
- 独立卸载返回后必须再次取得 `status=noinstall`，不能把退出码 0 当成卸载后置条件。
- 烟测使用唯一 appname，禁止复用现有生产应用。

## 审查清单

构建前：

- [ ] manifest 平台与实际内容一致。
- [ ] 无秘密、无无关元数据、无旧 FPK。
- [ ] 权限和资源声明最小化。
- [ ] 所有入口的身份与授权边界已说明。
- [ ] 原生依赖已按目标架构构建。

构建后：

- [ ] 两层归档均安全。
- [ ] `app.tgz` checksum 正确。
- [ ] ELF、Mach-O、PE 扫描完成。
- [ ] 外层 SHA-256 已生成。
- [ ] 报告不泄漏秘密。

部署前：

- [ ] 精确 host、appname、设备架构已确认。
- [ ] FPK 已审计且远端哈希一致。
- [ ] 数据保留、升级和回滚策略明确。
- [ ] 不会操作现有非测试应用。
