# 离线回归、真机取证与录屏

FnOS 应用的大部分缺陷不在"打包"，而在**生命周期竞态、状态口径、入口跳转**这三类。它们用眼睛看不出来，靠真机点一遍也常常不复现。本页记录可复用的验证方法。

## 分层

| 层 | 目的 | 手段 | 不该出现 |
| --- | --- | --- | --- |
| 离线回归 | 状态机、路由、跳转、页面渲染、源码约束 | `importlib` 载入口脚本真身 + 假 HTTP server + 打桩外部副作用 | 需要设备、需要网络 |
| 抽源桩测 | shell 分支逻辑（磁盘复用、令牌、扩容判断） | 从**源文件**抽出目标片段，配假 `virsh`/`qemu-img` 落盘断言 | 需要 root |
| 真机验收 | 平台记账、回调时序、性能基线 | 平台层 `appcenter-cli` 全流程 + 留痕取证 | 手工替换已装文件当验收 |

**真机验收必须走平台真实路径**（`uninstall` → `install-fpk` → `start`）。覆盖已装设备上的单个脚本来"验证"，只能证明那个脚本，证明不了安装回调、DB 回写和记账。

## 离线回归第一戒律

**不要用打桩替掉被测函数本体。**

真实事故：把地址发现改成"后台线程单飞 + 请求侧只读缓存"后，离线回归 **49/49 全绿**，真机第一次拿不到 IP 就死锁（发现链内部再次获取同一把不可重入锁）。之所以全绿，是因为每条用例都把整条发现链换成了不打桩的假函数——正好绕开了"链内部要拿锁"这段被测代码。修复（`Lock` → `RLock`）之后，用**原缺陷版本的字节**跑新用例是 4 FAILED，修复版 53/53 PASS，才算守住。

推论：

- 要测真身，就 `importlib.util.module_from_spec` 再载一份**独立模块实例**测它，别在同一个模块对象上把 `target_alive` / `resolve_ip` 换成桩之后还宣称测到了它。
- 需要"抓走原函数再打桩"时，先把原函数存成 `REAL_*` 常量，用例里显式调 `REAL_*`。
- 每次修完一个 bug，用例要能**在旧字节上失败**；否则这条用例是装饰品。

## 结构不变量用例

除了行为，还要断言"结构不许退回去"：

- 锁必须可重入；持锁调用发现链不死锁；请求收尾时锁没被占住（用 `acquire(timeout=…)` 断言）。
- 源码字符串约束：例如"入口脚本里不许出现 `udhcpc -n`"（netifd 托管接口上跑它会 deconfig 把地址和路由一起冲掉）、"控制路径不许被透传"。
- 页面注入约束：注入位置在 `<head>` 开头、大写 `<HEAD>` 也要命中、重复注入要幂等、没有 `<head>` 时兜底不崩。
- 前端改写脚本用 node 真跑一遍，断言若干组 URL 的改写结果，而不是只比字符串。

## 从源文件抽真身做桩测

shell 的生命周期分支很难整体跑（依赖 root、libvirt、平台环境变量）。做法：用 `awk` 从**源文件**里定位并抽出那段（起点用可唯一定位的行、终点用最近的缩进 `fi`），配假命令（假 `virsh`/`qemu-img`/`systemctl`，写文件代替真动作）执行并断言副作用；把 `sleep 5`→`sleep 0`、`-lt 12`→`-lt 3` 提速。**必须抽源文件**，不要复制一份副本测——副本会漂移。

桩测三个坑：

1. 被测片段里有 `exit` → 收尾必须把整段关进 `( … ) &` 后台子进程，否则 `$( … )` 命令替换里的 `EXIT` trap 输出会丢。
2. 被测函数用 `$( … )` 调用时，它内部的全局赋值（`SKIP_PROV`、`QCOW2_FILE`）会随子shell 消失 → 断言要么看它落盘/写的文件，要么改为读它打印的轨迹。
3. 片段里的调用带 `>/dev/null`，假命令的 stdout 断言收不到 → 假命令必须自己写文件才断言得到。

## 真机取证顺序

1. **在 `cmd/main` 里写调用留痕**（`arg` + `ppid`），这是判断"平台到底调了哪个动作"的唯一可靠手段，`ppid` 直接暴露 `trim_app_center`。
2. `journalctl -u trim_app_center.service` 看平台事件名（`APP_INSTALL_FAILED_INSTALL_CALLBACK_EXCEPTION`、`APP_START_FAILED_PORT_USAGE`、`APP_CRASH`、`APP_STOPPED`/`APP_STARTED`）。
3. 应用自己的状态文件（如 `/tmp/<app>.install.state`）+ worker 日志时间戳。
4. **延迟探针**：并排记录"平台/虚拟机真实状态落定时刻"和"入口页报出该状态的时刻"，才能证明响应从 20 秒降到 0.03 秒这类改善，而不是靠感觉。
5. 平台 CLI 调用的副作用要**前后对照进程 pid**，确认它没重启你的服务，才敢在请求路径里调。
6. 记账类问题看数据行与桌面入口表：见 [appcenter-state-db-runbook.md](appcenter-state-db-runbook.md)。

结论性判断必须由 1~5 支撑。**不要用"看起来正常了"交付**；也不要把自己抓包/观测的盲区当证据（例如在 OVS 内层口抓 DHCP 只见请求不见应答，是观测盲区而不是"网络没有 DHCP"，见 [vm-app-flow.md](vm-app-flow.md)）。

## 多变体矩阵测试

多镜像版本/多架构矩阵测试的做法与陷阱：

- 版本确证要看**权威来源**：domain XML 的 `<osVersion>`、或经串口读 guest 内发行版自带的版本文件（`/etc/*release` 一类），不要靠"我装的是哪个包"推断（磁盘复用逻辑会静默忽略你的选择）。
- 复用磁盘/复用 MAC 的实现会让 ARP 表残留上一轮的地址，**"ARP 里出现地址"不能当开机指标**，要用 TCP/HTTP 与落地时刻。
- 换盘/换配置测试前先整体留档原盘（`cp -a` + 记大小与 mtime），测完归位并复验；测试盘与用户盘分目录，别混。
- 记录每轮耗时（拉起到 running、入口判定就绪、浏览器落地）成表，才能区分"版本差异"与"噪声"。
- 全新装与复用路径要各测一次：全新装覆盖下载/校验/预置，复用路径覆盖保盘逻辑，两者分支完全不同。

## 竞态与并发用例

- 测试翻状态要**同时**作废被测实现的短时记忆（例如 1 秒开关机记忆），否则同一毫秒翻状态会让用例随机失败或假通过。
- 后台同步线程会迟到数百毫秒串下一个用例的台 → 用例之间加 `quiesce()`（等线程静默再清零）。
- 要桩 `subprocess.run` 时**替换模块全局命名空间里的引用**（`module.subprocess = SimpleNamespace(run=…)`），不要去动真 `subprocess`。
- 断言"不许抢方向盘"这类护栏，要构造"用户在窗口期里点了停用"的场景，而不是只看代码有 if。

## 录屏取证

用户报"点了没反应/跳错了/一直转圈"时，录屏比日志更能定位体验问题。

- playwright 起 `record_video_dir` 的 context，按目标设备设 `viewport` 与 `device_scale_factor=2`。
- **弹窗（`window.open`）是独立 Page，各自一份 video**：要录"点击 → 落地"就同时取两个 `video.path()`，各自 trim 后用 concat demuxer 拼。
- 点击前 `wait_for(state="visible")`，否则页面还在加载就点，录出来是半截白页。
- 页面正在跳转时 `page.content()` / `page.url` 不可靠：正文要 try 包裹，跳转判定用 `page.title()` 或逐秒日志。
- 转码统一 `ffmpeg -c:v libx264 -pix_fmt yuv420p -movflags +faststart`（通用可播）。
- `drawtext` 三个坑：`text=` 里**不能含冒号**（会把滤镜串切断），文案走 `textfile=` 最稳；`-frames:v` 的值必须是**字符串** `"1"`；本机若只有 Droid 中文字体则**不含拉丁字形**，中英混排要拆成两段 drawtext 分别指定字体。
- 判断视频是不是静止帧，别用整帧哈希（h264 噪声每帧都不同）；抽帧裁正文区拼条带用眼睛看。

## 文档与渲染校验

发布仓库的 README 也要验，尤其是自动生成的图与链：

- mermaid 上线前真渲染：`mermaid.render(id, src)`，**id 不能含小数点**（否则内部 `querySelector` 报无效选择器，看着像语法错）。线上确认法：抓仓库页 HTML 里的 `"errorMessage":null`。
- GitHub 告警块（`> [!NOTE]`/`[!TIP]`/`[!WARNING]`）是否被识别，看渲染 HTML 里的 `markdown-alert` 类名。
- 离线渲染自检 HTML 要加 `<base href="file://<仓库目录>">`，再用 playwright 查每张 `img.naturalWidth>0`，才算图片真加载。
- 外链逐条 curl。注意**下载站的目录索引可能 403 而真实文件 206 正常**，这种主机名不能做成可点链接（用户点开是 Forbidden 页），改成行内代码 + 指向可浏览的上游发布页。境外商店/CDN 本机超时属出口限制，别误判死链。
- 改文件前先比对本地与远端 **blob SHA**，别按记忆编辑（跨轮引用"它还有 X"必须先 grep 现场文件）。

## 工具与环境坑

| 坑 | 后果 / 对策 |
| --- | --- |
| 含删除、开关机、服务重启等动词的命令串可能被治理审批门拦下，超时即**终局拒绝** | 把动作换成平台层命令（`appcenter-cli stop/uninstall/install-fpk/start` + `cp -a`）或改成离线桩测；**不要改写命令措辞去绕过** |
| `cmd \| tail` 吞退出码 | 判定一律 `out=$(cmd); rc=$?` |
| `cat > A && cat > B` 共用一条 stdin 管道 | 第二个文件会被写成空；一个会话只喂一个文件 |
| 对 GB 级镜像/磁盘做哈希 | ssh 会话超时；用 `stat -c '%s %y'` |
| 文本替换工具是**子串匹配** | 改短标识符行（如 `_lock = threading.Lock()`）会连带命中 `_net_lock = …` 把文件改坏；必须带上下文行；参数被截断的编辑**可能部分落盘**，恢复用 `git checkout -- <file>` |
| `bash -c '…'` 内层语法错误 | 外层 `bash -n` 查不出；提出来单独检查 |
| `pkill -f 名字` | 会匹配到自己的命令行自杀；写成 `pkill -f "名[-]字"` 断链 |
| shell 辅助函数里裸赋值全局变量 | dash 的动态作用域会污染调用方；辅助函数变量一律 `local` |
| `PYTHONDONTWRITEBYTECODE` 未设 | `__pycache__` 被下一次打包带进 `app.tgz` |
| JSON 里写注释 | 没有注释语法，塞 `//` 会让整个索引解析失败；要下线某条目就把条目原文摘到单独文件里 |
