# 入口图标的设计方法论（细线 / 字母类品牌标）

本文回答"**图标本身怎么设计**"——尤其是笔画细、字母造型、透明底这类在 fnOS
桌面（约 52px 显示）天然吃亏的图形。槽位机制、取用路径与墨量判据见
[official-contract.md#图标与发布检查](official-contract.md)，本文不重复，只讲从
画稿或字母形态出发，到装机定稿的设计流程。素材来自一枚字母线描品牌标的完整
定稿过程（画稿 → 规范 → 多风格 → 光学加粗 → 装机），所有数字为该样本实测。

## 0. 先接受平台物理约束，再谈设计

- 平台全站只取 `{0}` 兜底槽，桌面与列表**同源**，没有"大细线 + 小实心"两个文件的机会。
- 显示尺寸约 52px 时，1.9px 以下的曲线几乎每个墨像素都落在抗锯齿过渡带
  （半透明墨占比 ≈80%），**这是几何决定的，换分辨率、锐化、硬边化都救不回来**。
- 唯一有效杠杆是在显示尺寸下增加墨量：笔画加粗、环/腔体填实，或换实心砖式构图。
- 设计开局的正确问题不是"好不好看"，而是"**这个构图在 52px 还剩什么**"。

## 1. 画稿 → 可验证规范

用户手绘稿定规范时，**别硬套几何原语拟合自由曲线**——直线残差 17~24、圆角半径
拟出两个互相打脸的值，就说明它本来就是自由曲线。可构造的做法：

1. **左右对称化**（以垂直轴镜像取平均，同时量化画稿本身的不对称量）。
2. **轮廓锚点表** + 参数样条：`x(t)`、`y(t)` 各做 PCHIP 插值，闭合曲线。
3. **用重建指标证明"这串数字能重画出这张图"**：IoU + 最大边界偏差。实测均匀
   步长 20（93 锚点/半）可到 IoU 0.9993 / 偏差 2.18px。
4. 抽稀档位要实测再写进规范：均匀步长 31 锚点时偏差跳到 13；Douglas-Peucker 在
   13~25 点偏差 22~149（样条外凸成瓣）；曲率自适应在像素抖动的边界上不收敛。
   **人手参考表可以精简，但必须标注它的重建残差**。
5. 导出 SVG（Hermite → 三次贝塞尔）后光栅化回比，确认矢量真源与锚点表等价。
6. **规范数字全部现场量，不抄旧版文档**：该样本的上一版规范被画稿现场推翻了
   七处（画布比例、底角角度、一个根本不存在的顶角、镜环中心距差 13%、字体、
   色值整体偏移）。

## 2. 品牌语义：元件从字形里"取"，不是往外"贴"

- 字母造型常自带品牌元件：拱＝耳朵、孔洞＝镜片/眼睛、中竖＝鼻梁。**先检查
  字形能白捡什么，再决定画什么**，加的笔画越少越稳。
- 不能把元件"粘"在笔画上——字母的"头"只是一条笔画，没有实心块可以长东西；
  要元件就得让**轮廓自己收尖/变形**（如尖拱用多边形一次成型：内外两条同心弧
  ＋两侧直边，等笔画宽，顶点自然是干净尖）。描边圆弧拼接必出接缝和小结。
- 借鉴成熟品牌标只借**构图语法**（转角元件、相切轮廓、比例关系），不复制轮廓。

## 3. 笔画层级：小图标失焦失身份的第一元凶

- **先量各元件的笔宽比**。该样本初版主体框 8 单位 ∶ 装饰环 52 单位 = 1∶6.3，
  主体框在 52px 下只剩 0.39px——小图标上"只剩配件、主体消失"。
- 层级原则：**主体承重结构 ≥ 装饰元件**。定版把主体加粗到能与环对话（12∶44）。
- "墨量层级"比"整体加粗"更优（实测）：装饰环 ×1.25 而主体不变，半透明墨占比
  74.5%→67.9%、总墨量几乎不变——**墨挪到承重结构，不是加墨**。
- 腔体/镜片填实是独立的墨量旋钮（与线宽解耦），小尺寸档可以填、母版档不填。
- 元件间的"脏点"感多半来自实心连接块与曲线上缘生硬相切——让横梁的端点沿被
  连接件的曲率收口（用布尔差集自然成型），比手工修形可靠。

## 4. 按槽位重绘（光学补偿），绝不缩放成品

- 每个槽位用自己的笔画档位**重新绘制**，再 LANCZOS 降到目标尺寸；64/128 档另加
  轻度 UnsharpMask。**不是把母版缩放**（缩放后笔画必然亚像素）。
- 档位表按显示尺寸折算笔画像素来定：让最细承重笔画在目标显示尺寸 ≥1.2px。
  示例档位（1024 口径主体笔宽）：`{512:12, 256:18, 128:22.5, 64:28, 兜底槽:24}`。
- 兜底槽（平台唯一取用的那个）按**它会被显示的大小**选档，不按它的像素大小。
- **光学参数的单位换算必须显式写死 + 断言**：该样本的参数从"距离变换值"换算到
  画布单位再到 SVG 描边宽各差一个倍数，混用一次就把线画粗了 16 倍，还被误读成
  构图问题。同一坐标域内的两种单位要分成两个命名映射，并打印期望值比对。
- "整体放大一点"要在**画布层**做（超采样缩放后裁剪再降档），笔画随图形同比放大；
  位图硬放大会糊。应用图标常规留白 10~12%，画稿定标的 15% 确实显小。

## 5. 深浅底双墨色

- **对比度要算不要猜**（WCAG：`lin(c)=c/12.92 | ((c+.055)/1.055)^2.4`，
  `L=.2126R+.7152G+.0722B`，`(L1+.05)/(L2+.05)`）。门槛分开：大面积实底 ≥2.0，
  细线 ≥3.0。
- 同一套墨在深底 10:1、白底 1.6:1 是完全正常的——**浅底深底必须分两套墨、两个
  文件**，不存在通吃变体。提亮墨色对亚像素线有直接收益（合成像素≈页面色与墨色
  按覆盖率混合，墨越亮线越"实"），实测峰值亮度 +15%，代价是大图品牌色偏白，
  所以墨色提亮也做成分档旋钮而不是全局。
- 细线稿在深底上**按尺寸各画各的**：缩到 64px 的细线会彻底消失；加粗有上限，
  超过约一个阈值耳部凹腔开始糊、相邻元件粘连——阈值要在自己的图形上实测。
- 白底贴纸的 2px 细描边救不回来（AA 摊薄后被对比度测量判 1.0）——浅底就**去掉
  白边只留投影**。不要为指标给图加看得见的描边。

## 6. 尺寸闸门（定稿前必过）

- 固定闸门：**64 / 32 / 16 三档 × 深浅两底**。64px 全部可读是底线；32px 允许
  细节降级但"是什么"必须还能认出；16px 细线曲线**必然**退化成色块——真要做
  favicon 就出"填实版/独立简标"，不要自欺。
- 判读用**渲染真页面**：放进真实显示尺寸（桌面 ~52、列表 ~40）和壁纸/列表行
  底色里看，不要只看单张大图。
- 给用户的选择图必须**同分辨率同管线**输出——两条链分辨率不同会被 QQ/聊天软件
  二次缩放，把分辨率差看成设计差（该样本曾被"放大版不等比"误判，实测放大前后
  包围盒比 1.0997/1.0988、IoU 0.9906，纯属发图分辨率不同）。

## 7. 真源与派生物一致性

- **SVG 真源承载母版比例**；装机槽位是光学重绘派生物。两者文件不同，但必须共用
  同一几何源（同一锚点表/同一参数模块 import），改图形只改真源。
- SVG ↔ 位图链对账用 IoU + 面积比，并会读：**IoU 恰等于面积比**说明你的掩码被
  成品完全包含——缺的是元件不是位移，别去找位移。残差 ≈1px 边缘级属渲染器 AA
  差异，描边只有几像素时 1px 边缘就值 0.03 IoU，不值得追。
- 位图链与 SVG 链的两个惯犯：布尔挖空（`A & B & ~C`）与按中心连线画的路径不等价
  ——SVG 端点要按挖空后的可见段算；抽稀点直接喂样条会因间距不均甩出 1px 抖动，
  要先按弧长等距重采样。
- 渐变在被缩放的 `<g>` 内定义时，`userSpaceOnUse` 坐标要做逆变换回写，否则色轴
  跟着缩放跑。

## 8. 交付与装机闭环

- 交付包结构：`svg/`（真源各档）＋ `png/`（与 SVG 同源渲染＋标准尺寸全套）＋
  设计文稿（几何、对比度、光学档、闸门、可复现命令）＋ 闸门拼图 ＋ SHA256SUMS。
- 装机后断言**槽位文件三方一致**：源码树 = 包内 = 设备（逐文件哈希）。桌面截图
  不可信——图标 URL 带 7 天 `immutable` 缓存。
- 设计与平台约束冲突时（细线在 52px 必然软），**出档位对比图让用户圈**
  （现状 / 加粗 / 填实 / 实心砖），不替用户拍板；每个档位是独立可回退的槽位文件。

## 9. 过程卫生（每一条都付过学费）

- 对称、居中、歪不歪的怀疑**先量化再讨论**（翻转 IoU、逐件角度测量）——肉眼判
  "明显偏左"实测中心只差 0.5px 的案例出现过多次。
- 数字对不上（枚数 ≠ 文件数、行数 ≠ 提交数）**先怀疑重复插入**，再怀疑算法。
- 改版**已验收**的设计时，公式照抄原件、只换参数；自写等价公式在满值处出过错。
- 体检脚本自身要有防假阳性断言：量轮廓对比度时半透明 AA 像素本来就 ≈页面色，
  必须 `alpha≥250` 再腐蚀取内圈，否则整圈被判 1.0；图形内部元素跟脚下的底比，
  不跟页面比。
- 归一化/缩放后的图再按原始坐标取证会错位——量化要在与绘制同一坐标系做。
